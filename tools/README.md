# API 문서 현행화

저장소 루트에서 Python 3.10 이상과 Node.js 22 이상으로 실행합니다. 가이드 변환용 npm 패키지는 처음 한 번 설치합니다.

```sh
npm ci --prefix tools/refresh
python tools/refresh/run.py
```

[출처 목록](refresh/sources.json)에 5.0, 4.22, 4.21, 4.20의 공식 API 개요 페이지, 문서 소스 인덱스, 릴리스 브랜치가 있습니다. 수집기는 실행할 때마다 브랜치의 최신 커밋을 확인하고 그 커밋의 API 인덱스와 상세 문서, 가이드 본문을 함께 읽습니다. 다운로드한 문서 원본은 `_scrape/sources/<커밋 SHA>/`에 캐시합니다.

API별 공식 페이지와 앵커는 `get_api.docUrl`에서 확인할 수 있습니다. 빌드 결과인 `data/versions.js`의 `VERSIONS.sources[버전]`에는 수집한 문서책 전체 주소, 원본 커밋과 커밋 날짜가 남습니다. 이 날짜는 문서 저장소의 변경 시점입니다.

수집기가 모든 버전의 인덱스·상세·필드·엔드포인트를 읽은 뒤 임시 디렉터리에서 카탈로그를 빌드합니다. 검증을 통과하면 같은 게시 작업에서 버전별 원본, 웹 캐시 파일, `data/`를 교체합니다. 파일 교체가 실패하면 이전 파일을 복원합니다. 검증된 버전별 JSON은 `_scrape/v<버전>.json`에 남으므로 오프라인에서도 `node build.js`로 다시 빌드할 수 있습니다.

```sh
node mcp/smoke.js
node tools/cons-audit.js --strict
```

새 제약 문장이 있으면 감사 결과에서 경로·원문과 유형을 대조한 뒤 기존 검토 기준선에 반영합니다. 새 릴리스는 출처 목록에 해당 버전의 개요 URL, 인덱스 URL, 브랜치를 추가하고 같은 명령으로 수집합니다.

[정기 갱신 워크플로](../.github/workflows/refresh.yml)는 기본 브랜치에 반영되면 매주 월요일 09:20(KST)에 실행되며 Actions에서 수동으로도 시작할 수 있습니다. 변경이 있으면 카탈로그와 웹 캐시 파일을 다운로드 가능한 산출물로 남깁니다. 배포는 기존 Pages 절차를 따릅니다.
